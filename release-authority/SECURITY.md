# Release Authorityのセキュリティ

本番で署名を有効にする前に [構成](docs/ARCHITECTURE.md) と [脅威モデル](docs/THREAT_MODEL.md) の未検証項目を確認します。このブランチは本番の経路やシークレットに接続されていません。

- 鍵は用途別に分離する。Play配布署名鍵はGoogle Playに残す。アップロード鍵がアクセス可能なのは承認されたSignerのみ。receipt、CIの認可、管理者の認証にアップロード鍵を流用しない。
- AABとAPKはCIで取り扱う。署名先への転送は検証・承認済みの固定CMS属性だけ。ループバックfixtureは毎回作るテスト鍵専用。
- 実運用では、信頼済みCI/Signer間のチャネル、監査/鍵のバックアップ、権限分離、失効、Artifact期限、Play結果照合が揃うまで署名を停止状態にする。
- JWT、Cookie、秘密鍵、認可Secretと未承認の署名入力をログや通知に含めない。脆弱性の報告は証拠に秘密値を含めず、リポジトリ所有者へ非公開で連絡する。
