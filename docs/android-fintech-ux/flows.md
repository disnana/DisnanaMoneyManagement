# 8つの目的で比べる操作フロー

起点は家計グループを選んだ状態のホーム。初回ガイド・端末のロック解除・OSの権限を済ませた人を想定する。マネーちゃんの回数は本番用Expoのルートとイベントから数えた最短手順。ボタン、タブ、行、入力欄へのフォーカスは各1操作。文字入力・スクロール・認証は別記する。競合の回数は公開ヘルプで起点と終点を確かめられた部分に限る。候補の件数や金融機関で手順が変わる箇所は固定しない。

| したいこと | 現行のマネーちゃん | 参考アプリで確認できた手順 |
| --- | --- | --- |
| ① 開いて資産を確認 | ホームで0回。非表示なら目を1回。選択家計の今日までの残高を合算し、カードのマイナスも含む。「現在の総資産」だけでは何を差し引いたか判断しにくい。 | Zaimはホーム→残高で1回。MoneytreeのAndroid案内では純資産の下に資産と負債の小計。MF MEの資産総額は負債を含まない。同じ名称や数字を各社で同義とみなせない。[Zaim](zaim-onebank.md)・[MoneytreeとMF ME](moneyforward-moneytree.md) |
| ② 今月の支出を確認 | 今月のホームで「月の収支」を読むまで0回、画面によってスクロール。下部の「分析」1回で支出タブが初期表示なら円グラフと内訳。カテゴリの根拠へは行をもう1回。 | Zaimとワンバンクは支出・分析の当月画面まで1〜2回。日本向けRevolutヘルプはホーム右上の分析→支払い金額の2回。支出と資産の推移で分母が違う。[家計簿2社](zaim-onebank.md)・[Revolut](revolut-android.md) |
| ③ 銀行口座を追加・管理 | 口座→口座を追加→口座名欄→保存の4回＋入力。初期値は銀行、残高は空欄なら0円。既存口座は「口座」→対象の2回で残高と明細に到達。金融機関名を入力しても自動取得は始まらない。 | Moneytreeは資産を金融機関から明細へ掘り下げられる。ワンバンクの銀行追加は取込開始範囲・規約・銀行選択を経て認証する。手入力の4回と銀行側の認証込み操作を比較しない。[Moneytree](moneyforward-moneytree.md)・[ワンバンク](zaim-onebank.md) |
| ④ レシートを撮って登録 | ＋から手入力は可能。撮影、画像選択、OCR、読み取った結果の確認の入口はこのmainにない。手入力を撮影の操作回数に換算しない。 | 権限付与済みのZaim Androidは記録→レシート→撮影→次へ→記録の5回。ワンバンクは読取後に日付・店・額を確認する。撮影UIの宣伝画像から処理時間は分からない。[Zaim・ワンバンク](zaim-onebank.md) |
| ⑤ 読み取った1品を修正 | 読取結果も品目モデルもない。保存済み支出のカテゴリ1個の変更はできる。 | Zaimは読み取り一覧からレシートを1回タップで編集へ。ワンバンクでは1商品ごとのOCRを公式資料で確認できず。Revolutの品目修正は割り勘に使う処理。[Zaim・ワンバンク](zaim-onebank.md)・[Revolut](revolut-android.md) |
| ⑥ 合計のみ／品目別を選ぶ | 現行の支出は金額・カテゴリを各1つ保存する。同じレシートを手で複数件にすると、元の決済との対応を保つ仕組みがない。 | MF ME Androidはレシート読取後に店／品目のどちらの一覧から保存するかで登録が変わる。Zaimの手入力の新規と編集では選べるモードが異なる。ワンバンクの明細のカテゴリ分割は読取とは別の操作。[MF ME](moneyforward-moneytree.md)・[Zaim・ワンバンク](zaim-onebank.md) |
| ⑦ 手入力・レシート・カード明細の重複を解消 | 設定→データ管理→Monemy CSVのプレビューで、同一取込先の再取込を判定できる。手入力の支出とカード個別明細を結ぶ画面はない。カード請求の引落を振替で記録する既存機能は、別の会計事象。 | Zaimは履歴から新着→明細→置換→レシート→確定の5回。確定後の取消に制限がある。Moneytreeのカード返済分類は銀行引落の二重計上への対処。二つの問題を画面でも区別する。[Zaim](zaim-onebank.md)・[Moneytree・MF ME](moneyforward-moneytree.md) |
| ⑧ 過去の取引を探して編集 | 取引→虫眼鏡→検索欄→結果行→修正欄→保存の6回＋入力。既定は全期間。メモ・カテゴリ・口座名も検索できる。該当行が初めから見えていれば虫眼鏡を経由しなくてよい。 | Zaimは履歴→虫眼鏡、履歴行→鉛筆→更新。Moneytreeは口座残高画面から全資産→検索欄の2回＋文字入力で全明細を絞れる。検索語や戻った時のスクロール位置は公開記事だけで追えない。[Zaim](zaim-onebank.md)・[Moneytree](moneyforward-moneytree.md) |

## 改善後にユーザーが確かめられること

| 目的 | 試す操作と画面遷移 | 迷い・誤操作を判定する観察項目 |
| --- | --- | --- |
| ①・③ 残高を知る | 「純資産」のすぐ下の内訳を1回で開く。口座は名前、右端の残高、最終行の合計の順に読む。口座行から当該口座の明細へ。手入力時の手順は維持する。 | カードの請求額を「銀行にあるお金」と答えないか。4件のプレビューを全口座の一覧と誤解しないか。非表示中の円額が読み上げからも消えるか。 |
| ②・⑧ 支出を振り返る | 月・対象家計を保ったままカテゴリ→寄与した取引→編集→戻る。先頭が振替手数料なら手数料だけを表示し、行から元の振替を開く。 | どの月の支出か、内訳を足すと上の額になるか。検索語・種類・元の行・読み上げフォーカスが戻るか。該当0件のときは「全条件を解除」を空の月と区別する。 |
| ④・⑤・⑥ 買い物を記録する | ＋→既存の支出入力→「レシートから」→撮影または画像選択→確認→保存。合計のみが初期。1品を直す人は同じ確認画面で品目別へ1回、対象行→訂正。保存ボタンに金額・内訳数を出す。 | 最速の手入力に余分な選択画面を挟まない。撮り直し・通信断・回転・Androidの戻るでも修正値が残るか。1品修正やモード往復後に金額を二度保存しないか。 |
| ⑦ 同じ支出を照合する | データ管理→取込プレビュー→候補の比較→「同じ支払いに紐づける」または「別の支払い」。後から詳細の「紐づけを解除」で戻せる。 | 同額同日でも別店舗・同店2回を誤統合しないか。ポイント利用時は額面・実請求を同じ行で確かめられるか。元明細と手入力メモが残るか。 |

比較試験では「先週パン屋で実際に払った額」「給料日前に口座にある合計」「明細が後から届いた買い物」の3つを、操作名を教えずに依頼する。正解したか、最初にどこを押したか、戻った回数、金額を読み違えた理由を記録する。銀行認証と読取失敗の待ち時間は操作時間から分ける。ここで示した操作数はユーザビリティ試験の実測値ではない。
