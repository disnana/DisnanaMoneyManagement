# DMM Turtle から取引履歴の設計に移せること

2026年11月22日に A01〜A15 の各 URL にアクセスした。14件は指定されたページの本文を直接確認できた。A08 の Community ファイルの内部は未確認で、作者が別途公開したキットの見本から確認できた範囲を記した。ポータルの各論は閲覧時点の β 版で、個別の改訂日が載っていないページは閲覧日を基準にした。

ここで扱う既存実装は `main` の `daf9d53`。ホーム・履歴・検索などは取引の表示に `TxRow` を使う。月間履歴では `TxGroups` が日別の囲い・見出し・明細を生成し、検索では `TransactionSearchList` が日別に仮想化する。支払いへのポイント充当、振替の元口座・先口座、長押しからの削除確認も既存の挙動である。以下の「適用」「確認」はこのアプリでの設計案・受け入れ条件を示す。

### A01　公式トップ

公式が対象として挙げているのは、ログインや決済など複数サービスにまたがる接点。同じ目的の操作を覚え直さずに済むことが、デザインの共通化による利用者側の利点になる。ホームでは最近の取引、検索では該当する取引という違いがあるが、同じ取引をタップすれば同じ編集画面に進む。この契約を共通にして、日付のまとめ方は各画面の閲覧目的に合わせる。以前共有された DMM TV の画面例から推測できる見た目と、公開資料が説明する適用領域は区別する。[公式トップ](https://turtle.dmm.com/)

### A02　はじめに

Turtle は画面ごとの学習コストと、作り手が似た画面を調査・再実装するコストを同時に扱う。横断的に再利用できる小さな部分に範囲を絞り、特定プロダクトの都合は利用側に置く。履歴の行・金額・編集入口には既存の `TxRow` を使い、月の移動、家計グループ、一覧とカレンダーの切替は月間履歴が管理する。レビューでは検索から開いた同じ ID と月間履歴から開いた ID の行き先・金額表示を照合する。ページ内の導入割合は2025年8月時点のプラットフォーム開発本部の数字である。[はじめに](https://turtle.dmm.com/about/introduction/)

### A03　デザイン原則

一貫性の基準には、設計者が使う名前・プロパティ、利用者に見える姿、操作後の結果の三つがある。そこで履歴の種類フィルターは「選択した分類」、日付は「見出し」、行は「該当する取引を編集」と役割を固定する。日付見出しと取引行が同じ押せる面に見える場合、日付には操作の記号を付けず、行だけに押下反応を返す。戻る操作後の対象月・選択中フィルター、読み上げ順、弱視でも把握できる金額の符号で評価する。デザインの例外にはユーザー側の目的と見直し条件を残す。[デザイン原則](https://turtle.dmm.com/about/design-principle/)

### A04　AI-friendly デザインガイドライン

役割名、Auto Layout、親幅への追従と最大幅を組み合わせると、幅の違う端末でも同じ内容構造を表現できる。透明にしただけの不要要素や、特定画面向けに固定した文字モードが生成結果に混ざる例もある。取引行はタイトル・補助情報・金額の順序を保ち、長い店名の折り返しと金額の配置変更を柔軟な幅で扱う。画面外に実体を置く隣月プレビューでは、視覚上の位置に加え押下とアクセシビリティのツリーからも除外できているか調べる。原文の HTML タグによる命名は AI-Turtle 独自の機能で、React Native の見出しにはプラットフォームのアクセシビリティ属性を対応させる。[AI-friendly デザインガイドライン](https://turtle.dmm.com/guidelines/ai-friendly-design-data/)

### A05　協業しやすいデザインデータ

少数件・充足・空・読込・エラーを先に洗い出し、実際に近い文字量と改行位置で設計を確認する。履歴の場合、「今月に取引がない」と「支出で絞ったら0件」は回復方法が違う。前者では月移動や記録、後者ではフィルターを戻せることを確かめる。少数件にはポイント充当の明細を1件、大文字には長い加盟店名・口座名・大きな金額を同じ行に入れる。初期読込と保存エラーは既存の状態管理で発生する場所を検証する。カテゴリ記号は既存の OS 別対応を使い、形状の微調整を行ごとに増やさない。[協業しやすいデザインデータの作り方](https://turtle.dmm.com/knowledge/user-friendly-design-data/)

### A06　既存サービスへの導入

既存画面のキャプチャに、利用者がすでに学んだ操作と色の意味を書き出し、小さい変更から実際の利用結果を取り込む手順が掲載されている。取引履歴では月スワイプ、中央の追加、タップで編集、長押し後の削除確認が基準になる。同一データ・テーマ・幅で日付の発見、1件を開く操作、キャンセル後の復帰を比較する。本文の社内 PoC の工数値は比較対象・計測環境が異なるため、今回の工数や速度の根拠には使えない。[DMM グループ内向け導入ガイド](https://turtle.dmm.com/getting-started/guides/)

### A07　公開リソース

作者は、Figma の設計資産、React の実装、挙動や使用例のカタログという用途を区別している。確認時の公式ポータルには UI Kit のリンクがあり、GitHub・Storybook の配布先は準備中だった。このアプリでは設計書に部品の入力・押下結果・状態、コードに型、比較試験に実データ形状を置く。これならカタログがなくても、レビューで「ポイント払いのメモがある行」から既存の `TxRow` にたどり着ける。[Turtle のリソース](https://turtle.dmm.com/products/resources/)

### A08　Figma Community の UI Kit

指定 URL の HTTPS 接続はこの環境のトンネルで 403、公開ウェブ閲覧でもファイル本文を取得できなかった。代わりに A07 に掲載された作者のギャラリー見本を閲覧した。サイドバーに色・グリッド・角丸・余白・文字の基礎と個別の部品が並び、ギャラリーでは各部品の実装状態を識別できる。設計候補に「既存部品・変更予定・検証済み」を記し、Figma に見本があるだけの案を利用可能な実装として扱わない。キット内の具体的な寸法・バリアント名・再配布条件は未確認。公式規約では、ライセンス表示がある資料、コード、ロゴやサービス画面の扱いが異なる。[Community ファイル](https://www.figma.com/community/file/1564449938298937268) · [作者の見本](https://turtle.dmm.com/assets/img/pages/products/resource/figma-kit.png) · [2026年7月28日制定の規約](https://turtle.dmm.com/extras/terms-of-use/)

### A09　デザイントークン

公式本文で確認できるのは、共通の最小要素を一貫した意味で使用する方針まで。詳細一覧は準備中だった。波及範囲を限定するため、マネーちゃんでは本文・補助情報・収入・支出・操作に現行パレットの役割を割り当て、履歴の境界はその画面で背景と判別できる色を選ぶ。`main` の Android では `separator` が透明なので、iOS の区切り線を同じ変数で移植するだけでは境界が消える。明暗両方で「日付のまとまり」と「押せる行」を実際に見分けられるか確かめる。[デザイントークン](https://turtle.dmm.com/products/design-tokens/)

### A10　コンポーネント

公開本文には、用途を組み合わせられる小さな単位を提供する方針があり、各部品の仕様一覧は準備中だった。家計簿の行には取引 ID、種類、金額、口座、必要なときだけメモを渡し、ポイント控除の計算には既存関数を使う。日計を表示する見出しは行と別の役割にする。購入と口座間振替を同じデータ形状だと見せてしまわないよう、振替先・手数料・ポイント表示および開く取引 ID の一致を照合する。[コンポーネント](https://turtle.dmm.com/products/components/)

### A11　AI と Turtle の実装事例（2025年8月5日）

記事で精度が上がった契機は、Figma 上のプロパティを実際の React props に変換する対応表を持たせたこと。幅を座標から推測するより意図を明示したプロパティを与えた方が安定した。これは Next.js などでの当時の事例である。こちらでは「メモを含む履歴行」を既存の `TxRow(tx, showMemo)`、「日付を含む行」を `showDate` に結び付け、表示文字列から種類を推測しない。必要な入力が型に表せるか、メモなし・長文・ポイントありで同じ部品を再利用できるかを見る。[DMM Developers Blog](https://developersblog.dmm.com/entry/2025/08/05/110000)

### A12　ポータル β 公開の報告（2025年10月28日）

開発チームは必要になった共通機能から順次入れ替え、採用に至らない組織にも、設計・運用の知見を共有するために公開した。今回の採否はライブラリ移行の有無より、月間履歴の操作を改善した上で、既存の検索・ホームから同じ編集機能に入れるかで判断する。共通行を触る際は、この2画面も回帰確認に含める。記事が説明する公開時点と、現在 A07 で利用できる資源を混同しない。[DMM Developers Blog](https://developersblog.dmm.com/entry/2025/10/28/110000)

### A13　Turtle の開発と運用（2024年12月2日）

チームは見本の会員登録を入力から完了まで実装した結果、部品を個別に眺めるだけでは見つからなかった使いにくさを修正できた。また設計、実装、マニュアルに同じ色値を三重に持つ問題を、ひとつの元データから生成する仕組みで解消した。家計簿では履歴から取引を開き、変更または取り消して同じ明細に戻るところまでを設計の見本にする。色値は該当する OS のパレットに置き、文書や試験で同じカラーコード表を手書きしない。記事の社内スプレッドシート・GAS の導入はこの画面の前提にしない。[DMM Developers Blog](https://developersblog.dmm.com/entry/2024/12/02/110000)

### A14　Android チームのコードレビュー事例（2025年6月6日）

DMM ポイントクラブの実例には、Compose の余白の多重適用、非同期試験の `runTest`、`AndroidView` の初期化と更新の違いがある。色を初期化でしか設定しないと、表示中のテーマ変更に追随しないという指摘だった。Expo 側でも画面を閉じずにライトからダークへ切り替えて日付・金額・アイコンを確認し、OS の Insets とリストの内部余白が二重になっていないかを調べる。Kotlin 試作で View を組み込む場合だけ、その色更新を `update` でテストする。余白をまとめる際は押下領域を変える Modifier の順番も点検する。[DMM Developers Blog](https://developersblog.dmm.com/entry/2025/06/06/110000)

### A15　設計者・開発者への取材（2026年4月28日更新）

第三者メディアによる当事者への取材。担当者は、新規ページに比べ既存ページの一部分だけを正確に変える作業には難しさが残ったと説明している。本アプリでも UI の改修前に、月の状態を所有する場所、日付集計、各行の編集遷移や支払いの内訳を確認する。変更を月間履歴に限定する場合、検索結果やカレンダーの行まで意図せず変わっていないか、同じ取引で比べる。記事は開発チームの体験談であり、ネイティブのフレーム性能を比較した資料ではない。[unprinted.design のインタビュー](https://www.unprinted.design/articles/dmm-turtle-ai-design-system/)
