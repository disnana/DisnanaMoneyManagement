# マネーちゃんの取引履歴を読みやすくする

2026年11月22日。基準は `main` の `daf9d53`、試作は `design/mobile-research-ledger`。27画面の操作経路を調べ、月の家計と一件ごとの支払いを同時に確かめる「取引」を代表画面に選んだ。調査、実装、同じ架空データを使った確認をこの順で記録している。

## 日付から取引をたどる仮ブランチ

`prototype/history-by-date` は上記の研究ブランチから分けたExpo版の試作。取引を開くと、日付の隣にその日の最初の店名と金額が現れる。同日の明細は店名の位置にそろい、日計と淡い帯で一日が終わる。月の収支をタップすると収入・支出を開ける。ポイント充当と実支払は一覧で比較でき、メモの付いた明細をタップすると編集画面で全文が読める。

文字倍率を考慮した幅が348dpを下回ると、日付を明細の上、金額を店名の下へ移す。さらに文字が大きいと種別を2列に組む。同じ5件を使ったExpo Webの確認では、幅393pxで最初の店名が画面上端から378pxの位置から253pxへ移った。320×568と412×915で日付・店名・金額が重ならず、検索・前月・グループ・支出フィルターの各操作領域が48×48px以上であることを確認した。[確認スクリプト](history-web-check.mjs)

## この画面で確かめた設計

月の範囲と収支を同じ背景にまとめ、その下に種別で絞れる明細を置いた。日をまたいでも店名と金額の位置がそろう。ポイント充当を含む取引は額面と実支払の両方、振替は元本と手数料を読める。中央の＋や編集・削除は既存の操作につながる。タブで移動すると今月に戻り、同じ明細を編集して戻ると選択月を保つ。[取引タブ](../../apps/mobile/src/app/%28tabs%29/transactions/index.tsx)・[日別一覧](../../apps/mobile/src/ui/TransactionHistoryList.tsx)

Expo SDK 58 を採用した判断には、5件の同じ家計を使った。Expoの月支出は5,680円。Flutter試作ではポイントと振替手数料の扱いに計310円の差があり、Kotlin試作は振替を表現するモデルを持っていない。今回の変更は既存の会計・保存処理を使い、表示する行を画面付近に絞る。1万件での遠端移動、実機のスクリーンリーダー、両OSでのGPU性能は、それぞれに適した条件で評価する。[技術比較と再現データ](review-native.md)・[大量明細の計測](web-validation.md#大量明細)

実装コミット `dd35d1c` の GitHub Actions は全ジョブ成功。モバイルの型検査と両OSのHermes出力、WebのビルドとE2E、共有テストを含む。ローカルでは134件の単体テスト、変更対象16ファイルのESLint（9.39.5、eslint-config-expo 58.0.4、エラー・警告ともに0）、Android・iOS・Webの本番用エクスポートを確認した。iOSはバンドル生成までを検証した。[CIの全ジョブ](https://github.com/disnana/DisnanaMoneyManagement/actions/runs/44992415556)

## 他の画面に広げる順序

今回の実装は取引履歴まで。次の画面では、余白や字の大きさに加えて「この金額はいつの、どの家計の、何を含む金額か」を共通の判断基準にする。

| 次の対象 | 適用する設計 | 次に進む前に確認する操作 |
| --- | --- | --- |
| 1．検索結果・口座の明細 | 店名・金額・口座の並びと取引行の読み上げを履歴にそろえる。検索期間や対象口座は結果件数の近くに置く | ヒットした明細を開き、取消で検索語・期間・スクロール位置に戻る。対象外の月の取引が混ざらない |
| 2．カード詳細・ホーム | カード詳細では「選択した請求月の残額」と「現在の利用可能額」を別見出しにし、いちばん目立つ操作を支払いの記録にする。ホームの総資産は現在値として伏せ字設定を保つ | ポイントと現金を併用し、引落額、カード未払い、口座残高を照合する。ホームでは金額を隠した状態で画面を開き直す |
| 3．分析 | 月と家計の位置を履歴に合わせ、グラフのそばに単位と合計を置く。同じカテゴリの明細へ移るときに選択条件を引き継ぐ | 支出比率の1項目を選び、対応する明細との合計を照合する。色を識別しにくい場合も名称・金額・割合が読める |
| 4．登録・編集・貯金 | 入力欄のラベルとアイコンの列を共有。個人／事業の選択と、その結果入力できる勘定科目・事業割合の間に見出しと余白を設ける。貯金は既存の計画内で目標の選択・編集に進む | 下部と右上の登録から同じ1件だけが保存される。IME表示中の最終欄、取り消し、削除確認外のタップ、保存失敗後の入力保持を両OSで試す |

各段階は画面単位のコミットに分ける。取引履歴と同じ架空データを使い、現行版からの操作数、変更前後の画面、保存した金額を照合してから次の共通化に進む。[現行の操作回数と保存時の挙動](audit-and-flows.md)

## 試す

SDK 58 に対応した Expo Go で起動し、画面下の「取引」を開く。

```sh
git fetch origin
git switch design/mobile-research-ledger
cd apps/mobile
bun install --frozen-lockfile
bun run start
```

比較データはすべて架空。端末で同じ月を試す場合はテスト用の空のプロファイルを用意し、ルートから次のコマンドで JSON を作る。設定 → データ管理 →「バックアップから復元」で読み込み、取引タブで2026年11月を選ぶ。50、1000、10000件も同じ生成器で作れる。[データ生成器](history-fixture.mjs)

```sh
node docs/ui-research/history-fixture.mjs 5 2026-11 > /tmp/mane-history-5.json
```
