# Android 取引履歴の比較試験

対象は Expo の取引タブ。変更前は `daf9d53e9039ee386413dd15970cc85c3176d516`、比較対象は `dd35d1c`。画像は会話で共有する。リポジトリには検証条件と結果を記録する。

## 比較条件

- Android 10（API 29）の x86_64 Android SDK 仮想端末。主画面は 1080×2424 px、420 dpi（約411 dp幅）。GPU は SwiftShader、CPU はソフトウェアエミュレーション。物理端末の入力遅延・FPSをこの環境から推定しない。
- 同じインストール済み Expo Go、Expo SDK 58。変更前後のブランチから独立した Metro が Hermes バイトコードを供給する。取得した manifest の URL は `dev=false&hot=false&minify=true&transform.engine=hermes&transform.bytecode=1` を含む。Go の起動、バンドル取得、JS 評価の時間が含まれるので、本番 APK のコールドスタートの測定には使わない。
- 架空の共通入力を `node docs/ui-research/history-fixture.mjs 件数 2026-11` で生成。隔離した Expo Go の保存先を退避し、停止中に同じ取引・メタデータを SQLite へ投入。データ設定・集計の製品コードは両版共通。画面の年月は2026年11月、家計グループは「すべて」。比較画像の5件に収入・支出・振替・手数料・ポイント・長い店名・メモを含めた。
- 標準フォントは 1.0。小画面は720×1600 px、320 dpi（360 dp幅）、文字1.4。中画面は1200×1800 px、320 dpi（600 dp幅）、文字1.0。ライト／ダークはアプリから指定し、PNGの実背景色も照合した。
- スクリーンショットは `screencap -p`、読み上げに渡るラベル・状態・境界は `uiautomator dump`。権限のある物理端末や接続済みの端末ファームはこの環境にない。仮想端末にもTalkBack音声サービスは導入されていない。音声順序・実指での探索・OLED実機・iPhoneについては個別の実機レビューが必要になる。

## 実機での再計測

1. 同じ端末で、変更前後を同じビルド種別・表示倍率・ナビ方式にそろえる。Actions等の画像アップロードは不要。テスト用の空のインストールに架空の JSON を取り込み、取引タブで11月を選ぶ。実データの上書きは避ける。
2. 5件で `青葉ベーカリー` のポイント200円・実支払1,080円、月収入268,000円・支出5,680円・収支262,320円、グループ・種別・カレンダー・前月・戻るを操作。TalkBack で選択中の種別、支出と収入の区別、日付、長い店名、符号・手数料を確認する。明細タップ、中央の＋、入力、キーボードを閉じて戻る経路も確認する。
3. 同一条件の PNG を `adb -s SERIAL exec-out screencap -p > history.png` で作業用フォルダに保存。UIツリーは `adb -s SERIAL shell uiautomator dump /data/local/tmp/history.xml` と `adb -s SERIAL pull /data/local/tmp/history.xml` で収集できる。小画面・文字拡大・ダークで表示範囲、金額、セーフエリアを対照する。
4. 性能は同じリリースビルド条件、同じ端末・リフレッシュレート・温度、50 / 1,000 / 10,000件で測る。アプリを開いたまま `adb shell dumpsys gfxinfo PACKAGE reset`、縦方向の往復スクロール、`adb shell dumpsys gfxinfo PACKAGE framestats`。独立に複数回実施し、母数と分布を保存する。Perfetto の FrameTimeline（対応OS）、Main/UI・RenderThread と JS のトレースで外れ値の原因を分ける。別端末・デバッグホストの絶対msからフレームワークの優劣を決めない。

## 実行中に見つかった不具合

11月の取引から前月を開くと、画面には「2026年10月」「0件」「今月に戻る」が描画された一方、Androidのアクセシビリティツリーにはヘッダーと下のタブだけが残った。画面に見える翌月の位置をタップして11月へ戻すと年月・フィルタ・取引のノードが復帰した。PNGとUIツリーの両方を照合したことで、描画停止と読み上げ対象の消失を区別できた。月ごとに親を画面幅ずつ無制限に移動する構造を見直し、前・当・翌月が親の範囲内に入る構造に改めた。

## 比較用バンドルの識別

Metro が Expo Go 用の複数のmanifestに同じ資産キー `bundle` を出したため、ポートを変えても直前のコードを使うケースがあった。比較用の端末ホストでは圧縮した実バイトコードのSHA-256を資産キーに入れ、エミュレータへダウンロードされたファイルを照合した。家計データ・アプリのソースにはこの配信処理を含めていない。異なるコードを表示していた中間キャプチャは比較から除外した。

| 画面 | Hermes バイトコード | SHA-256 |
|---|---:|---|
| main | 8,282,990 bytes | `bf17606c35646ad48acf644e046214f5ec901fbe5d960901bc19ef7d6b651192` |
| 更新版 | 8,328,610 bytes | `6050d57aa91ee1ca876129b5c3f1124575b887e38326988a54364ffa858693a3` |

サイズはこのホストで使ったAndroidバンドルのもの。Google Playの圧縮配信量やAPKサイズとは条件が異なる。

## 金額・表示領域の照合

5件で11月の収入は268,000円、支出は手数料110円を含めて5,680円、収支は262,320円。青葉ベーカリーは支出1,280円、ポイント200円、実支払1,080円。現行版の検索・カレンダー・前後月の領域はそれぞれ44 dp、家計グループと種別は高さ36 dp。端末ツリーのピクセル幅を表示密度 2.625 で割った値で、デザイントークンの読み替え値ではない。

コントラストはAndroid側のテキスト・背景色の組を相対輝度で計算した。白背景の通常文字16.66:1、補助文字5.60:1、支出6.54:1、収入6.87:1。ダークの行背景ではそれぞれ13.94:1、7.24:1、9.63:1、7.97:1。明細行に役割・収支種別・金額・口座・ポイント/メモを一つのラベルとして渡し、種別は文字・選択状態でも区別する。これは静止した配色の結果で、写真・実機輝度・読み上げ音声の評価を含まない。

標準ライトで検索、カレンダー、前後月は48×48 dp、種別と家計グループは高さ48 dpを実測した。青葉ベーカリーはクリック可能な `android.widget.Button` として「青葉ベーカリー、支出、-¥1,280、生活口座 · 食費、ポイント充当 ¥200 · 実支払 ¥1,080」、振替は「財布へ現金を移動、振替、¥20,000、生活口座 → お財布、手数料 ¥110」と公開された。見出しは日付に日計、種別選択時は対象種別を含む。

同一画像の先頭行上端は現行983 px、最終版1,018 px。新しい月収支に強弱を付けた案を端末上で一度見直し、月・グループ名・収支・二つの補助指標を整理した。修正前の試作では1,235 pxまで下がっていた。最終版では同じ初期画面内で4件目の振替と手数料まで見える。

現行は11月から前月・翌月のどちらへ1回移動しても本文の読み上げノードを失い、11月に戻ると再出現した。最終版は11月→10月→9月→10月、年月選択→5月→今月に戻る、指を画面中央で左右にスワイプする経路で各月の年月・種別と空状態のボタンがツリーに存在した。前後月プレビューの見出しの二重読み上げを防ぐため、いずれも「年月を選ぶ」が1個であることを確認した。

ホームと分析の11月から前月へ移動しても各画面固有の見出しがツリーに残った。取引で10月を表示中に同じタブを再タップ、または検索を開いてAndroidの戻るキーで閉じると、どちらも10月を維持した。ホームへ切り替えて取引を開き直すと双方とも11月になった。

Androidで収入のみに切り替えると給与1行、振替のみに切り替えると手数料110円を含む振替1行になった。元の明細→編集→戻る、検索→戻る、一覧→カレンダー→一覧も通過した。別の操作では中央の＋から734円を入力した。IMEの表示とEditTextの値を照合し、右上で登録して6件、削除確認のキャンセル後に改めて削除して5件・支出5,680円に戻った。

## ネイティブ描画の測定条件

ゲストのRAMは2 GiB、ホストのCPU割当は4コア相当。各データ量はアプリを停止して入れ替えた。月の金額と先頭の店名がツリーに出た時点で準備完了とし、初回のExpo Go起動・読み込みはフレーム集計から外した。50件は両版で月収入268,000円、月支出42,750円、月収支225,250円。候補は1,000件（収支−571,470円）と10,000件（収支−8,108,970円）においても、金額と読み上げ可能な先頭明細が一致した。

最初に `adb shell input swipe` で420 msのジェスチャーを送った試験では、受け側がタップを受理して11月21日の振替編集へ遷移した。編集画面は画像にもツリーにも残っていた。この方法のパーセンタイルとPerfetto記録は一覧の比較から除外した。画面名と明細行の座標が変わったことを毎回確認できる試行だけを比較値に使う。

### 明細の移動を確認した計測

Android UI Automator の `UiDevice.swipe` を70ステップで実行した。指の横位置は画面中央、高さは表示領域の76%と48%。上・下・上の順に3回、それぞれの直前に `dumpsys gfxinfo host.exp.exponent reset` を行い、ドラッグ終了から0.7秒後にフレームを取得した。前後に「取引を検索」とクリック可能な店名・口座の組があること、行の座標が変わったことを毎回照合した。50件の先頭行の上端は main で983→377→983→377 px、試作で1,018→412→1,018→412 px。収録時のホストの1分負荷平均は0.98～2.09だった。

| ---: | --- | --- | --- | --- | --- | --- |
| 50 | main | 73 / 76 / 75 | 224 / 224 | 150 / 150 / 133 | 200 / 200 / 200 | 360.3 → 363.9 |
| 50 | 試作 | 71 / 76 / 74 | 221 / 221 | 125 / 101 / 150 | 200 / 150 / 200 | 355.5 → 371.4 |
| 1,000 | main | 先頭明細の確認が時間枠を超過 | — | — | — | — |
| 1,000 | 試作 | 74 / 74 / 74 | 222 / 222 | 150 / 117 / 125 | 200 / 150 / 200 | 352.4 → 368.5 |
| 10,000 | main | 1,000件の結果を受けて試行を見送り | — | — | — | — |
| 10,000 | 試作 | 74 / 73 / 74 | 221 / 221 | 150 / 150 / 150 | 250 / 200 / 250 | 365.4 → 375.1 |

main の1,000件では、起動後174秒以内にラベル付き先頭明細を取る条件を満たせず、最後のツリー取得を含め191.6秒で試験を終了した。1万件の試作は月収支の照合と3回のドラッグに成功した。Androidで全1万件を末尾まで連続閲覧する試験は行っていない。末尾の取引IDの照合は[Web側の試験](web-validation.md#大量明細)で実施した。

50件のp95の試行中央値は両版とも200 ms。ソフトウェア描画のエミュレーターでは全フレームが遅延判定となり、通常件数での滑らかさの向上は確認できなかった。PSSにはExpo Go、Hermes、描画資源、共有ページの按分も含まれる。50件ではスクロール後のPSSが試作で7.5 MiB多かった。

50件では、画面移動を別途照合した22秒のPerfettoトレースを各版1本採取した（`sched gfx view input wm`）。対象のExpo Goプロセスで `DrawFrame` は main が71区間、試作が74区間。区間時間の中央値／p95は91.10／129.72 msと69.68／127.76 msだった。これらの区間時間と上表のフレーム全体の時間は別の指標であり、各1トレースから端末でのFPSやGPUの改善率は算出していない。

| 条件 | 実際に確かめたこと |
| --- | --- |
| 幅360 dp・システム文字140% | 月の主額、家計グループ、収入、支出が縦に並ぶ。ベーカリーの店名・金額は別行になり、ポイントと実支払は次の行に折り返す。スクロール後に書店の長い名前・3,860円・メモを含む読み上げラベルを取得した。初期画面に見える明細は標準文字より少ない。 |
