# Codex向け・モバイルUI品質向上リサーチパック

最終調査日: 2026-11-22（JST）
用途: DMM系サービスのように統一感・操作の自然さ・情報密度・完成度が高い家計簿アプリを設計・実装するための、一次資料と具体的な開発指示をCodexに渡す。

## 読む順序

1. `SOURCES_FULL.md`: 参照した公開資料へのURL、確認できた内容、読む目的、実装への反映条件。リンクは削除せず、各資料の原本を確認する。
2. `DETAILED_DESIGN_AND_ENGINEERING.md`: UI、インタラクション、画面構造、実装、最適化、テストの具体的な知識と検討項目。
3. `CODEX_START_PROMPT.md`: Codexにそのまま渡すメイン指示。既存ソースコードを検査してから判断する。

## 重要な前提

- DMMのTurtleは主にDMMのログイン・決済などのプラットフォーム領域に関するデザインシステム。DMMの全Android/iOSアプリにそのまま使われていると断定しない。
- Turtleの公開Figma UI Kitは利用可能だが、公開ページでGitHub ReactライブラリとStorybookの配布リンクは「準備中」。非公開ライブラリを使えると仮定しない。
- Expo SDK 58の`@expo/ui`はReactから本物のJetpack Compose/SwiftUIの部品を使える。ただし、全画面が自動的にCompose/SwiftUIへ置き換わるわけではない。
- SDK 58へ無条件にアップグレードしない。既存アプリのバージョン・依存関係・テスト環境を確認すること。
- 出典が2025年のものには2026年の最新APIと異なる記述があり得る。具体的な使用方法は対象バージョンの公式ドキュメントを優先する。
- 参照サイトを丸ごと複製する必要はない。出典へのリンク、こちらで独自に整理した検討・設計事項、Codexによる再確認を組み合わせる。
- UIの良さはフレームワークだけでは決まらない。既存Expoプロジェクトを壊しての作り直しを先行させず、同一画面の比較試作で判断する。

## 現時点の推奨

- 既存アプリの改善: **Expo + React Native + Expo Router**を第一候補として維持。
- Androidネイティブ品質の参照実装: **Kotlin + Jetpack Compose**で代表画面を別プロトタイプとして作成。
- Android/iOSで同一描画コンポーネントを最優先する新規開発: **Flutter**を比較対象に残すが、既存Expo資産を捨てる理由は要検証。
- モデル: 設計や資料・技術選定はGPT-6.2 Astra。大量反復、画面ごとの実装・修正はGPT-6.2 Sol。工程の境界でレビューする。

## 比較評価の必須条件

- 必ず同じダミーデータ、画面幅、文字サイズ、ライト・ダーク両テーマ、同じ画面遷移を使って比較する。
- 比較画面: ホーム（予算・残高・最近の取引）と、取引履歴（多件数リスト）を第一候補。
- 評価軸: 情報の見つけやすさ、タップ数、視認性、戻る/キーボード操作、スクロールの安定性、開発工数、保守性、アクセシビリティ。
- デバッグ画面の体感のみで性能を判定しない。リリース相当で測る。
