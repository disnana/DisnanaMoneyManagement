# 脅威モデル

本書はユーザーの仕様書にあるモデルの補足です。変更元の既存リリースコードと、別ブランチに追加したローカルPoCを対象にしています。

| 脅威 | 検証済みの防御 | 実環境で必要な確認 |
| --- | --- | --- |
| 侵害されたBuild CIが自己申告のハッシュを渡す | 信頼済みツールで別途AABからマニフェスト・JAR署名属性を再計算。manifestの固定と署名時の一致検査 | ビルドと検証の管理者・runner・GitHub App権限を分離し、検証CIでartifact ID、run、署名付き来歴を独立照合 |
| Secret漏洩、偽JWT、別CIからの実行 | JOSEでRS256、固定issuer/audience、時刻、GitHubの不変ID、caller/ref/reusable workflowのSHA、runを照合。Secretとの両方を要求 | GitHubが発行する実トークンのclaimで確認。用途別Secretの配布、ローテーション、JWKSキャッシュと失敗時のメトリクス |
| 署名属性やAABを差し替える | exact bytesの比較、署名の公開鍵検証、全エントリの単一署名検証、content SHA比較。変造と過大入力を拒否 | 独立Verifierが同じartifactと署名属性を生成する経路。汎用HTTP署名経路を与えず、検証済みCMSの結果を署名用状態に束縛 |
| 承認ページの漏洩・クリックジャッキング・CSRF | JWT認証アダプター、厳格なOrigin/Fetch Metadata、GETで承認は進まない、CSPとエスケープ、同一管理者と短命nonce、8秒経過 | Access保護ホストのみ公開、workers.dev/preview/迂回経路無効、IdP MFA、短命セッション、本物のSafariと実経路で検証 |
| 再送・並行操作・署名後クラッシュ | SQLiteで状態と台帳を同時書き込み、署名予約は1件。再取得は保存結果。結果不明は隔離。監査の書き込み異常は署名前に停止 | Private Signerだけに予約・確定Capability、本物のDOで再起動・障害・キルスイッチの持続性、孤立した予約の復旧手順 |
| Play認証またはPublisherが侵害される | 既存下書きコードの誤trackや誤hash拒否のモック。別鍵receiptがPlay応答と対象を束縛 | WIFとアプリ単位権限、検証済みの証跡を要求してからPlayに接続。Playの権限粒度による他トラックへの影響を確認 |
| 過大入力・DoS | ストリーム上限、固定長検査、署名枠・TTL、未認証の永続書き込みを避ける構成 | WAF、実測でCPU/リクエスト/DO枠を確認し、制限に達した際に停止する |
| Cloudflare管理者またはSignerが侵害される | 署名鍵とreceipt鍵の用途分離。ローカル台帳は連鎖を検査できる | 管理アカウントのMFA、デプロイ権限分離、独立保管先へのチェックポイント、緊急停止とPlayのアップロード鍵リセット |

GitHub OIDCはジョブの身元を証明します。ソースや依存の安全性には、独立検証とレビューが要ります。Verifier自体が侵害されると偽の証明を登録できるため、管理境界と固定SHAが必要です。Worker Secretsはハードウェア鍵保護を提供せず、Signerの実行コードや特権管理者は鍵を扱えます。Cloudflare内に閉じた監査連鎖は特権者による全書き換えを防げません。

長押しは誤操作防止であり、サーバーが実際の長押しや新しい生体認証を証明する仕組みではありません。Accessセッション盗難の影響にはMFAとセッション期限の実設定が必要です。署名演算とDB永続化を跨ぐ物理的なexactly-onceは保証できません。
